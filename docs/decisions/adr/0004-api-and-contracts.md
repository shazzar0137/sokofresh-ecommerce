# 0004. API style: REST + OpenAPI contracts generated from the backend

- Status: Accepted (2026-11-26); **amended by ADR-0011** (OpenAPI version as produced by drf-spectacular; same-origin routing)
- Date: 2026-11-26
- Decided by: Project owner (Danny)

## Context
Frontend and backend are separate applications and must not drift apart.

## Options considered
- REST + OpenAPI: simple, cacheable, well-tooled.
- GraphQL: flexible queries, more complex security and caching.
- tRPC: TypeScript-only; incompatible with a Python backend.

Evidence and sources: `../../research/TECHNOLOGY_RESEARCH_2026-11.md`.

## Decision
REST/JSON under `/api/v1/`. OpenAPI 3.1 generated by drf-spectacular and committed to `shared/contracts/openapi.yaml`. Frontend types generated with openapi-typescript. Contract tests with Schemathesis in CI. Breaking changes need a new version and Architect approval.

## Consequences
- Contract changes surface as type errors and failing tests.
- Hand-editing the contract file is not allowed once generation is in place.
